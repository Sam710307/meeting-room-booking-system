企业会议室预约系统

软件规格说明书（SPEC）

轻量级 · 纯前端 + Node.js 桥接

1. Problem Statement（问题陈述）

小型团队（10-30 人，1-3 间会议室，部门内部使用）在会议室预约中面临四个核心痛点：

  • 冲突频发：多人同时预约同一会议室，撞车后临时协调困难
  • 资源不透明：不知道哪些会议室空闲、能坐多少人
  • 流程混乱：预约没有统一入口，有人口头、有人微信群、有人贴纸条
  • 利用率低：会议室被长期"占着不用"，真正需要的人反而订不到

2. Proposed Solution（方案描述）

构建一个轻量级会议室预约系统，提供统一的预约入口，支持日历/列表两种视图查看可用时段，先到先得规则自动检测冲突并推荐替代选项，站内消息实时反馈预约状态，替代现有口头/微信群等混乱预约方式。

4. Core Features（核心功能）

核心功能清单
编号 功能 说明
F1 用户注册/登录 用户名+密码，用于身份标识和"我的预约"隔离
F2 快速预约 选时间段 → 选会议室 → 填会议主题 → 完成
F3 先查后订 查看各会议室可用时段后，选定空闲时段再预约
F4 日历视图 周视图/日视图，时间格子展示已占用/空闲
F5 列表视图 按会议室列出可用时间段，文字列表形式
F6 视图切换 日历视图与列表视图自由切换
F7 查看我的预约 列出自己所有预约，含时间和会议室
F8 取消预约 随时取消，释放时段
F9 修改预约 改时间或换会议室
F10 冲突检测 同一会议室同一时段，先到先得，拒绝后提交者
F11 推荐替代 冲突时推荐其他空闲会议室或邻近时段
F12 站内消息 预约成功/取消时在系统内弹出提示
F13 数据持久化 JSON 文件存储，重启不丢失

5. Technical Constraints（技术约束）

技术约束
约束 说明
前端 纯前端单页应用，HTML/CSS/JS，双击即用
后端 轻量 Node.js 单文件服务，负责读写共享 JSON
存储 JSON 文件，数据共享，支持跨人冲突检测
部署 每人本地双击 HTML 打开，后端服务部署一处即可
环境 本机已安装 Node.js，无需额外依赖

6. Non-goals（明确不做的事）

  • 不做审批流程（预约提交即生效）
  • 不做会议室设备管理（不维护投影仪、白板等清单，会议室仅显示名称）
  • 不做外部通知（不发邮件、不接企业微信/钉钉）
  • 不做数据统计报表（不做利用率分析、趋势报表）
  • 不做管理员角色
  • 不做访客/外部人员预约

7. Success Criteria（成功标准）

成功标准
编号 标准 验证方式
S1 团队成员能完成注册、登录、预约、查看、取消、修改全流程操作 功能测试
S2 数据持久化，重启后不丢失 重启验证
S3 同一会议室同一时段冲突检测准确，后提交者被正确拒绝 冲突测试
S4 冲突时能推荐替代会议室或邻近时段 推荐测试
S5 日历视图/列表视图切换正常，可用时段展示准确 视图测试
S6 站内消息在预约成功/取消时正确弹出 消息测试
S7 跨用户数据共享正常，A 的预约能被 B 看到 共享测试
